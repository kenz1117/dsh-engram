## 2. 新发现

### P1（2 项，用户直接感知）

**P1-1 · 两个运维卡片实例化了永不渲染的私有 toast。**
`PalaceLanguageCard`（EngramPanel.tsx:3909）与 `PluginLanguageCard`（:4446）各自 `useToast()`，
唯一挂载的 toast viewport 在 EngramSection（:6319）。宫殿切换、向量重算、底座修复、
词典创建/编辑/保存的成功与失败提示全部不可见——昂贵/破坏性操作「按了没反应」。
修法：照 OpsTab（:4705/:4716）把 section 级 controller 传下去，删两个私有实例。

**P1-2 · 向量道是每次查询 + 每次写入都跑的全表线性扫描。**
`vectorPool`（sqlite.ts:717-725）`SELECT *` 全部活跃向量、逐行反序列化新 Float32Array、
JS 逐行余弦。N=10k/d=384 ≈ 每扫 15MB 垃圾 + 380 万次 FMA；engram_search scope=all 最多
12 次扫描，写入路径 decideWrite / findContradictions 再各扫一遍。1 万–10 万条开始疼。
修法：sqlite-vec vec0 虚表（行业标配），或过渡方案：进程级缓存打包 Float32Matrix +
单循环 typed-array 点积 + 候选上限。

### P2 · 数据与稳定性

- **N1 · op_log 无索引、无保留策略；telemetry 每次物化最多 60 万行。**
  op_log 是唯一没建索引的表（sqlite.ts:446-459），hasAudit（WHERE op+detail，:567）每个
  摄取回合跑两次全表扫；aggregate.ts:40-56 每次 /telemetry 六处 recentOps(100_000) 同步
  物化（node:sqlite .all() 同步，阻塞整个 DSH 进程），面板概览+热力图+计数瓦片都拉它。
  修法：三个索引（op,detail / target_id / at）+ at>=since 下推 SQL + 自动保留窗口。
- **N2 · restore 与活连接竞态 + 多进程失效不传播。** routes.ts:1694-1697 swap 文件时旧
  连接还开着，窗口内写进 .before-restore-* 静默消失；所有 DSH 进程共享全局 dbDir 的前提
  下，A 进程 restore 后 B 进程连接仍指旧 inode（F16 的多进程版）。修法：close → swap →
  惰性重开；flock 或 checkpoint-busy 检测拒恢复。
- **N3 · openEngramStore 中途失败泄漏 db handle。** sqlite.ts:379-529 只有两条早退路径
  close；初始 DDL、迁移语句、computeStoredDim 抛出时句柄悬空，Windows 上 EBUSY 砖死
  后续 restore 直到重启。修法：post-open 全体包 try/catch close。
- **N9 · attachEmbeddings 绕过 guardDimension 且不刷新 storedDim。** sqlite.ts:1516-1525
  写裸 BLOB；import/backfill 换模型后写进混维度向量，此后每次搜索静默降级纯关键词，
  面板无解释。修法：逐条 guard + 末尾重算 storedDim。
- **N10 · 单个损坏 BLOB 行让整个 engram_search 抛错。** blobToVec（:220-222）对长度非 4
  倍数的 BLOB 抛 RangeError，读路径 catch 只放过 DIMENSION_MISMATCH（:928-929）；
  computeStoredDim（:521-528）已预期此类行，读道没有。修法：池 SQL 加
  LENGTH(embedding) % 4 = 0。
- **N11 · embedder 失败/hang 缓存整个进程。** index.ts:984-996 一次
  `.catch(() => undefined)`：瞬时网络故障=纯关键词检索直到重挂载；本地 pipeline() 加载
  无超时（local.ts:62），下载 hang 则 save/search 无限等待。修法：AbortSignal.timeout +
  失败惰性重建（stores 的重试范式已有，index.ts:923）。
- **N12 · runConsolidation 每天全池 O(N²) 余弦 + N 次单条 embedding。**
  consolidation/run.ts:62-151 逐条 embed([content])（几千条=几分钟事件循环阻塞）；
  :78 用 forget（墓碑语义）而每日衰减用 archive，同_criteria 两种状态语义。修法：批式
  embed + 候选上限 + archive 语义（reflect.ts: 批 30/池 300 已示范）。

### P2 · 工具面与安全

- **N13 · 注入防护只包一半读工具。** renderMemoryPacket 包了 search/facts/timeline/
  review（create.ts:772, 963, 1055, 1103/1138, 1437），但 engram_examine 裸返回完整记忆
  原文（create.ts:1837-1846，保真度最高的外泄通道），engram_neighbors（:1878）、
  engram_tour（:1945/:1979）、engram_audit_forgotten（:1307）、engram_review_queue
  （:1349）、engram_stats（:1516）同样裸奔。修法：全部记忆内容出口过 renderMemoryPacket。
- **N14 · engram_save 的 importance 完全不验证。** create.ts:616 / :476 无范围与有限性
  检查，NaN 通过 typeof 检查；store 落盘也不 clamp（sqlite.ts:857）。importance: 42 永久
  霸榜 topActive 进 session-start 注入。修法：clamp 0–1 收敛进 store.write 单点。
- **N15 · engram_search 的 limit 无界。** create.ts:687 裸 input.limit ?? 8；其余列表参数
  都走 parseCountParam。修法：clamp（1–50）。
- **N16 · import 不走 redact/sanitize 纪律。** create.ts:1665-1670 与 routes.ts:1136-1141
  直写 importData；第三方导出/前脱敏时代数据带协议标签和密钥进宫再被 turn_start 注入。
  修法：import 时重洗（redactedView :1536-1539 已示范）。
- **N17 · 错误分类不一致。** 多数错误带下一步提示（好），但仅少数带机器码（EngramError，
  create.ts:2096 / index.ts:1382,1471），agent 无法程序化分支。
- **N18 · 路由载荷无界。** GET corridor 返回 exportAll() 整库含全文（routes.ts:1208-1237）；
  GET health 为数边数调 exportAll()（:1178）；GET timeline 最多 500 条全文（:895-916）。

### P2 · 前端

## 3. 对标 GitHub 同类项目

| 维度 | 同类做法 | dsh-engram 现状 | 结论 |
