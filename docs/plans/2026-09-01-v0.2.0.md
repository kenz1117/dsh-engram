# dsh-engram v0.2.0 实现计划（二期：自动摄取 + 飞轮 + 审计）

设计依据：`docs/design.md` 的自动摄取、矛盾检测、知识飞轮、审计隐私章节。一期（v0.0.1）已交付：双库存储、混合检索、5 工具、画像注入。

## 关键设计决策（实现前锁定）

1. **摄取触发点**：复用已验证的 `agent/pre-step` waterfall——`step === 1` 即新一轮开始，上一轮已完整。读取 `agent.session.events`（日志，遵守 model-visible ⟺ logged）提取上一轮候选事实。异步 fire-and-forget，不阻塞请求；失败计数不重试。
2. **LLM 路由**：从会话日志最近一条 `request/header` 的 `data.header.config.{provider,model}` 解析（路由同样来自日志）；Config 可选 `provider`+`model` 成对覆盖。LLM 经 `ctx.llm.stream` + `BlockAssembler`（session-title-llm 样板），`purpose: 'engram-ingest'` / `'engram-distill'`。
3. **摄取档位**：`ingest: 'off' | 'light' | 'eager'`，默认 `off`（opt-in 不进发行默认）。light = 只从用户消息提炼、每轮上限 2 条、confidence 0.3；eager = 用户+助手消息都提炼、上限 5 条、confidence 0.4。
4. **矛盾检测**：写入时向量近邻（cosine ≥ 0.88，同 scope active）→ 建立 `contradicts` 边（from=新 to=旧）→ 工具结果报告候选，由模型/用户裁决（update 或 forget），不阻塞写入。
5. **命中强化**：检索命中在 touch 时 confidence +0.05（封顶 1）。
6. **蒸馏**：`engram_distill` 显式触发。取 active 条目按 importance 排序前 30 → LLM 输出 JSON 规律数组（kind=skill|fact，supersedes ids）→ 新条目写入（向量=被合并者平均），旧条目 archived + supersedes 边，confidence 继承均值。
7. **衰减**：启动时 + 每 24h 定时（`ctx.effect` interval）：active 且 importance < `decayImportanceBelow`（默认 0.3）且 lastAccessedAt 超过 `decayAfterDays`（默认 30）→ archived。
8. **schema v2**：nodes 表加 `source_round INTEGER`、`source_seq INTEGER`（摄取来源归属）；`SCHEMA_VERSION = 2`，旧库拒绝加载（pre-release stance）。
9. **审计工具**：`engram_review(id)`（条目 + 来源链 + supersedes 邻居 + 该 id 最近 20 条操作日志）、`engram_stats()`（kind/status 分布、边数、信噪比）、`engram_export(format)`（写 `dbDir/exports/` 文件，返回路径+摘要，不把全库塞进上下文）、`engram_distill(scope)`。

## 任务分解

- **T1 store 层**：schema v2、WriteInput/MemoryRecord 扩展、`touchConfidence`、`review(id)`、`stats()`、`exportAll()`、`decay(options)`、`findContradictions(embedding)`+`linkEdge()`、`supersedeMany()`（蒸馏用）。测试：store.spec 扩展。
- **T2 摄取**：`src/llm/client.ts`（stream 封装 + JSON 解析容错）、`src/ingest/hook.ts`（上一轮事件提取 prompt + 档位逻辑 + 候选写入）。测试：假 LLM fixture。
- **T3 矛盾检测**：接入 store.write 路径（有向量时），返回候选报告。
- **T4 蒸馏**：`src/flywheel/distill.ts`（聚类提炼 + supersedeMany）+ decay。测试：假 LLM。
- **T5 接线**：4 个新工具、Config 扩展（ingest/provider/model/decay/distillMaxInput）、入口 inject 加 `llm`、pre-step 挂摄取、decay 定时。测试：tools.spec 扩展。
- **T6 收尾**：composition 测试（9 工具 + llm 替身）、README、v0.2.0 提交。

## 已查证的 API 事实

- `ctx.llm.stream({ provider, model, messages, system, maxTokens, sessionId, purpose, signal })` + `BlockAssembler`（`packages/session/session-title-llm/src/index.ts` 样板）。
- 会话事件形状：`request/header` → `data.header.config.{provider,model}`；`user/message` → `data`；`turn/start` → `data.turn`（`packages/client/ui-usage-billing/tests` 与 `time-context` 样板）。
- `agent.session.events` 可直接读（time-context 样板）；`agent.session.id` 为 SessionId（`String()` 归一）。
- pre-step waterfall：`next()` 必调、reject 分流（一期已落地）。
