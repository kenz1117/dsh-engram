# dsh-engram v0.7.2 实现计划（真·记忆宫殿：桩位 + 间隔重复 + 固定巡游 + 门牌规则）

动机：v0.7.x 的宫殿元素（意象铭牌、走廊图、动态巡游）只存在于叙事/展示层，召回与强化路径（importance 排序注入、RRF 检索、命中 +0.05）与宫殿逻辑无关。本版本把记忆宫殿的**信息架构**落进内核——宫殿对 AI 的价值是四件事：用位置当索引、用固定路线定顺序、让骨架长期复用、让每个标记独一无二；感官/情绪维度是人脑补丁，AI 不需要，不计入质量分。

架构对齐（用户供图「目录即房间，路径即路线」）：
- **主厅·常驻核心记忆** = 画像注入（top N 每轮在场），渲染标注「主厅常驻」。
- **走廊·路由索引** = engram_search 的 room 参数 + engram_stats 的房间目录：先决定进哪个房间，再房内检索，不一上来全库扫。
- **房间** = kind 分房（事实厅/偏好阁/决策堂/往事廊/技法坊）+ 满员扩建；scope 分库对应「按人/按项目」的宫殿群。
- **门牌规则** = 唯一 · 差异化 · 带日期；禁止两条记忆近似到无法区分（save 时即时评分 + 提示，refurb 兜底）。

## 关键设计决策（实现前锁定）

1. **schema v6 加六列一表**（全可空/带默认，迁移零数据搬运）：
   - `slot_room TEXT` / `slot_index INTEGER`：桩位（房间 + 房内序号）；NULL = 未排桩（存量条目由 backfill 一次性排桩）。
   - `imagery_score REAL`：意象质量分（save 时启发式计算落库，refurb 低分规则的数据源）。
   - `next_review_at INTEGER` / `ease_factor REAL` / `interval_days REAL`：SM-2 调度状态；NULL = 未进入复习调度（存量条目不排期，保持旧 decay 行为）。
   - `CREATE TABLE tour_routes (position INTEGER PRIMARY KEY, node_id TEXT NOT NULL)`：固定巡游路线（每库一条，append-only；条目归档/遗忘时巡游渲染跳过，不删位置——宫殿的桩位不因一件物品移除而塌掉）。
2. **SM-2 简版（src/review/sm2.ts）**：grade 0-5；≥3 通过，间隔 1 → 6 → round(prev × ease)；<3 重置间隔 1 天、reps 清零；ease 下限 1.3。信号源：`engram_report`（success=5 / failure=1，新增可选 `grade` 参数显式自评时优先）。save 时新条目初始排期 `next_review_at = now + 1 天`（`reviewScheduling: false` 关闭）。
3. **decay 联动**：进入复习调度的条目（next_review_at IS NOT NULL）不参与自动衰减——到期未复习的记忆该被优先复习而非归档；其退出由翻新清单 demote 规则（人工确认）接管。
4. **排桩规则**：默认房间按 kind 映射（fact→事实厅 / preference→偏好阁 / decision→决策堂 / episode→往事廊 / skill→技法坊），房间容量 9（7±2 上限），满员自动开 `<房名>-2` 并记 op_log。存量 backfill：按 kind 分房、created_at 定序，幂等（只处理 slot_room IS NULL）。
5. **engram_tour 双模式**：`mode: 'thematic'`（现状，查询驱动动态路线）/ `'fixed'`（按 tour_routes 表顺序走全宫，逐站报桩位）。save 时自动 append 路线。
6. **检索练习闭环（agent 侧）**：新工具 `engram_review_queue` 返回今日到期队列——只给线索（房间 + 桩位 + 意象铭牌 caption），**不给内容**；模型先尝试回忆，再用 `engram_review` 揭示核对、`engram_report grade` 自评。画像注入与画像行内带桩位号（`<房名> #<序号>`），会话首轮若有到期条目在注入末尾附一行「今日待回忆 N 段」。
7. **门牌规则（src/imagery/score.ts）**：0-1 启发式——caption 有效（4-30 字）且全库唯一 +0.4、带日期/时间锚点（YYYY-MM-DD 或「X年X月」等）+0.3、与同房其他门牌差异化（前 6 字不与既有 caption 重复）+0.3。感官挂念与情绪权重**不计分**（人脑补丁，AI 不需要），字段保留兼容。< 0.5 时 engram_save 输出附增强建议，refurb 新增低门牌规则。
8. **编码特异性线索**：search top5 命中附同房间相邻桩位（slot ± 1）id 列表；工具输出与画像行带「刻于 <日期> · <房名> #<桩位>」。
9. **路由索引**：engram_search 加可选 `room` 参数（房内检索；缺省全库保持兼容）；engram_stats 输出房间目录（房名/桩位数/最近门牌）作为「先决定进哪个房间」的决策依据；画像注入渲染标注「主厅常驻」。
10. **面板**：新增「今日待回忆」卡（GET /api/engram/review-due；揭示 → 自评 记得/模糊/忘了 → POST review-answer）；宫殿陈展列表加「按巡游路线」排序开关。

**与计划的偏差**：决策 5 提到的「tour-proposal 读固定路线」未实施——`engram_tour mode=fixed` 已覆盖固定路线巡游，入殿导航仍按 importance×confidence 排序。决策 7 的「刻于 <日期>」落在 `engram_search` 命中行；画像注入行与 `engram_stats` 房间目录只带「房间#桩位」坐标，不带日期锚点（日期在画像行属于常驻成本，收益不足）。两项均非阻塞，留给后续版本按需补。

**实证发现的缺陷（已修）**：用工具执行器跑一遍 agent 真实调用序（save → stats → search room → tour fixed → review_queue → report grade）时暴露——`engram_save` 单条路径在无门牌提示时返回的对象**丢掉了 `text` 字段**，模型只看到 `{id, kind, importance}`，看不到刚落成的桩位坐标；批量路径的 `items` 同样不含桩位。两处已改为始终回带坐标的提示文本（批量 `items` 加 `slot` 字段并同步 output schema 与汇总文本），并补了断言。（临时实证脚本跑完已删除，不入库。）

**迁移回归（用户现场报错 `no such column: slot_room`，已修）**：v6 的两条建索引语句（`nodes_slot` / `nodes_review_due`）曾放在**迁移之前**的建表 exec 里；新建库的表已含 v6 列所以无事，但任何旧库打开时列还不存在，exec 直接抛错——迁移根本没机会跑，库停在半迁移状态（`tour_routes` 已建、列未加、版本号仍 5）。修法：两条索引移出前置 exec，新建库分支里补建，旧库由 `MIGRATIONS['5']` 随加列一起建。原先的迁移测试用「当前版本建库再降版本号」模拟旧库，列其实已存在，因此漏检；已补一条**真实 v5 结构**（手写 SQL，无 v6 列）的迁移测试覆盖此路径，并验证迁移后新写入可正常排桩、索引就位。用户的 6 个真实库（含两个 v2 老库，走完整 v2→v6 链）已就地迁移验证通过：版本 6、7/7 列、存量条目补排桩并登记巡游路线。

**issue #1（会话 dispose 时进程 fatal exit）**：报告者给出完整堆栈与根因，复核后确认当前代码仍有该缺陷。链路：`session/disposed` 观察器是 fire-and-forget 且**未挂 `.catch()`** → `ingestFinalTurn` 在 try **之外**调 `lastTurnNumber(deps.events)` → dispose 后事件源已 detach 使 events 为 undefined → `turnStarts` 读 `events.length` 抛 TypeError → async 函数返回 rejected promise 无人接管 → 宿主 `installFailLoud` 视作致命错误 `process.exit(1)`（同一缺陷在 preStep 路径因有 `.catch()` 只降级为告警，故表现为「重复告警后突然退出」）。三层纵深修复：① `turnStarts` 对 undefined 按空日志处理；② `ingestFinalTurn` 把取轮次也移进 try，使该函数**永不 reject**（取不到轮次时不落 pending——键需要轮次号，只跳过）；③ dispose 调用点补 `.catch()` 兜底。回归测试两条：单元层覆盖 undefined 事件源不抛、组合层用真实 Loader + `snapshotEvents: () => undefined` 断言不产生未处理 rejection。已验证测试有效性——临时回退三层修复后组合测试复现出与 issue 完全相同的堆栈并被 vitest 记为 `Errors 1`，恢复后全绿。
