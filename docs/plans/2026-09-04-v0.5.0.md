# dsh-engram v0.5.0 实现计划（竞品对标：项目标识 + 摄取闭环 + 注入预算 + 排序 boost）

设计依据：三家 memory 类竞品源码/文档调研（hindsight coding-agents、OpenViking dsh-memory-plugin、dsh-mnemon）对比报告。结论：三者均依赖外部服务器/daemon/云端 embedding，dsh-engram 的「单进程、纯本地、可离线」是差异化定位，不学其架构，只吸收四项低成本高收益设计（原报告 P0 清单）。P1/P2 候选见文末，不在本期范围。

已核实「无需做」项：① 回声污染防护——摄取已跳过 plugin 注入快照（`src/ingest/hook.ts`）；② durable 归因注入——画像已是 `createUserMessage` + `source: { kind: 'plugin', plugin, form: 'snapshot' }`（`src/index.ts`），不会被 `complete: true` preset 静默吞掉，无需迁移注入通道。

## 关键设计决策（实现前锁定）

1. **项目标识改用 git origin**（学 OpenViking workspace-peer）：`projectKey` 解析顺序 = git origin URL 归一化 → cwd 哈希兜底。归一化规则：去协议与凭证、host 小写、去尾部 `.git` 与 `/`（`git@github.com:a/b.git` ≡ `https://github.com/a/b`）；worktree 时 `.git` 为文件，沿 `gitdir:` 指针 + `commondir` 找到真 config 再读 origin——纯文件读，不起子进程。库文件名 `project-<sha256(origin)前24hex>.db`。**迁移**：启动时 origin 库不存在而 cwd 旧库存在 → 同目录 rename 迁移（零数据搬运）；两者都存在 → 不动并 `console.warn`（不合并，避免静默冲突）。无新配置项。
2. **末轮摄取闭环**（学 OpenViking final commit，消掉 README Known Limitation #1）：`session/disposed` 观察器摄取最后一轮（切片 = 最后一个 `turn/start` 到日志末尾，复用 `ingestPreviousTurn` 的提炼管线）。**幂等**：op_log 记录已摄取 `(sessionId, turn)` 键，摄取前查重，normal 路径与 disposed 路径互不重复。**兜底**：disposed 是 fire-and-forget 观察器，进程退出可能打断——5 秒 `AbortSignal.timeout`，失败/未完成的 pending 键留在 op_log，下次会话首次 pre-step 时重放补做。失败仍只告警，不影响对话。
3. **注入 token 预算 + 降级行**（学 OpenViking recallTokenBudget）：新增 `injectTokenBudget`（默认 1024，clamp 128–8192）。token 估算 `ceil(len/4)`。装填顺序按 importance 降序；整行超预算跳过该行继续试更短行（不截断 content）；预算耗尽后剩余条目折成一行索引（`- [kind] #id 前40字…`）+ 末尾 `+N more; use engram_search`。`profileTopN` 保留为条数上限，先取候选再按预算装填，两者同时生效。
4. **检索排序乘性 boost**（学 hindsight TEMPR 尾部）：RRF 融合分之上乘两个因子——recency `1 + w_r * max(0, 1 - daysSince(lastAccessedAt) / decayAfterDays)`、proof `1 + w_p * log2(1 + accessCount)`。系数入 Config：`rankRecencyWeight`（默认 0.2）、`rankProofWeight`（默认 0.1），clamp 0–2，0 即关闭。纯排序层改动，`last_accessed_at`/`access_count` 字段已存在，**SCHEMA_VERSION 不变（仍为 2）**。

## 任务分解

- **T1 项目标识**：`src/project/identity.ts`（origin 读取/归一化/sha256 哈希 + worktree 指针解析 + cwd 兜底）；index.ts 分库改名 + 旧库 rename 迁移 + 双存 warn。测试：identity.spec（归一化等价类、worktree 指针、无 .git 兜底）、迁移测试（构造旧库文件断言 rename/warn 分支）。
- **T2 末轮摄取**：hook.ts 切片支持「最后一轮到日志末尾」；op_log 幂等键 `(sessionId, turn)` 查重；`session/disposed` 钩子（5s 超时）+ 下次会话 pre-step 的 pending 重放。测试：假 LLM fixture，覆盖幂等不重复、disposed 超时落 pending、重放补做。
- **T3 注入预算**：config.ts 加 `injectTokenBudget`；renderProfile 改预算装填 + 降级索引行。测试：预算截断、跳过超长行、降级行格式、中英混合估算。
- **T4 排序 boost**：search 排序层乘性 boost + config 两个系数。测试：recency/proof 各改变序、系数为 0 退化为现状。
- **T5 收尾**：README/README.en 更新（删掉 Known Limitation #1，新增三个配置项说明）、design.md 同步、composition 测试扩展、v0.5.0 提交。

## 已查证的 API 事实

- `session/disposed(session)`：scoped emit 观察器，fire-and-forget，宿主不等待回调（`packages/core/session/src/index.ts:62`；样板用法 `packages/session/session-title/src/index.ts:372`）——故 T2 必须有 pending 重放兜底。
- 画像注入现状：`createUserMessage({ content, source: { kind: 'plugin', plugin: name, form: 'snapshot', sections } })`（`src/index.ts:89-92`）。
- 当前分库命名：`project-${Buffer.from(process.cwd()).toString('hex').slice(0, 24)}.db`（`src/index.ts:107`）。
- 摄取切片现状：最后两个 `turn/start` 之间（`src/ingest/hook.ts`）；末轮切片 = 最后一个 `turn/start` 到 `events` 末尾。
- op_log 已有 `audit(action, id, detail)` 通道，幂等键与 pending 标记直接落 op_log，不加表。

## 后续版本候选（本期不做）

- 近重复自动合并：余弦 ≥0.97 档自动走 supersedes 合并（hindsight reconcile），与 0.88 矛盾档分流。
- 摄取活动信号准入：结构信号（字符数/工具数/多样性）低于阈值不调辅助 LLM（mnemon 后台审查准入）。
- git 分支维度可见性：nodes 加 `branches` 列，注入/搜索按当前分支过滤（mnemon 独有，需 schema v3）。
- 蒸馏证据链：distill 产物记录被合并者 id 列表为可回溯证据（hindsight observations）。
- 冷热容量分层：字节预算驱动归档/回填（mnemon）；向量 ANN 索引（sqlite-vec，规模上来后再评估）。
